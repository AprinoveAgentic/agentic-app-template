## Environment variables

Copy `.env.example` to `.env`. In production, all secrets live in AWS Secrets Manager
(`/<app>/<env>/<key>`). Never commit `.env`.

## Database migrations

Migrations live in `apps/api/migrations/` and run with `node-pg-migrate`.
Name them sequentially: `001_description.sql`, `002_description.sql`.

All migrations must be backward-compatible with the previous app version.

## Deployment

On merge to `main`, GitHub Actions builds Docker images, pushes to ECR,
and updates the ECS services in QA automatically.

Configure these GitHub repository variables before first deploy:

| Variable | Example |
|----------|---------|
| `ECR_REPO_API` | `agentdp-my-app-api` |
| `ECR_REPO_WEB` | `agentdp-my-app-web` |
| `ECS_CLUSTER` | `agentdp-qa-cluster` |
| `ECS_SERVICE_API` | `agentdp-qa-my-app-api` |
| `ECS_SERVICE_WEB` | `agentdp-qa-my-app-web` |

And this repository secret:

| Secret | Value |
|--------|-------|
| `AWS_DEPLOY_ROLE_ARN` | IAM role ARN for OIDC deployment |
